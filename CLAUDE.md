## 5.2 Units and frames

mm, degrees, seconds, grams. No other units in code.
MAT frame: origin bottom-left of mat, `+X` right, `+Y` up, heading `0° = +X`, CCW positive.
Robot pose `(x, y, θ)` at the drive-axle midpoint. Object pose = base centroid + `upright: bool`.

## 5.4 Ambiguity register

Full register with reasoning: `docs/AMBIGUITIES.md`.

| ID | Ambiguity | Conservative default |
|---|---|---|
| A1 | "moved" is defined as *no longer touching initial position* AND *no longer upright*, but the rulebook photos award 0 to a clef that fell over while still in place | implement as **OR**; expose flag `moved_semantics: "or" \| "and"` |
| A2 | "upright" has no angular definition | `ASSUME:` tilt ≤ 15° from start pose; parameter `upright_tolerance_deg` |
| A3 | Does the robot overlapping a target area at time-out break "completely in"? | `NEEDS-VERIFY(S4)`; default: robot is not "an area on the mat" |
| A4 | Must the robot return to start to stop the clock? Where does time sit in tie-break? | `NEEDS-VERIFY(S4)`; default: score first, then time |
| A5 | Do objects still held by the mechanism at time-out score? | `NEEDS-VERIFY(S4)`; default: **no** |
| A6 | Max motors/sensors, start-size envelope, EV3+SPIKE mixing | `NEEDS-VERIFY(S4)`; **no final robot design before this is answered** |

## 5.6 Scoring model (frozen v1, from S1 — for reference, not to be implemented yet)

Max 255. Cables 2×15=30 (partial 5). Microphone 20 (partial 10). Instruments 3×15=45.
Notes 6×20=120 (partial 10). Bonus: clef 10, speakers 2×10=20, amp 10.
`completely in` = object touches the target area **and no other area on the mat**.
Notes are 120/255 = 47% of total. Bonus 40 pts is 40 pts permanently at risk on any path
crossing the stage. Every mission has 50% partial credit.

Randomization: notes `black, white, yellow, blue` are randomly assigned to the 4 light-green
squares on the upper edge ⇒ **4! = 24 permutations**. `green` and `red` are fixed.

## 5.7 Anti-patterns

1. Citing general-rules facts from memory (S4 is absent)
2. Stating any coordinate or dimension not measured from S2
3. Claiming one strategy beats another without simulator evidence
4. Hard-coding coordinates anywhere other than `field_spec.json`
5. Optimizing for 255/255 without reporting `P(success)`
6. Prose paragraphs where a table or diagram fits
7. Forgetting that partial credit is 50%

## Working conventions

- **Keep `docs/plans/ROADMAP.md` current as part of "done".** Any task that closes or
  materially advances a phase must reconcile the at-a-glance diagram, the phase table and
  `last_reviewed` in the *same* unit of work — not as a follow-up. This is
  documentation-currency for decisions already made; it never licenses a new decision.

  `docs/extracted/`. Change `tools/pdf_extract.py` and re-run.
- One commit per phase, conventional-commit messages.
